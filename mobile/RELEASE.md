# Shipping Word Search for StagWare (Android)

App identity lives in `app.json`:

| Field | Value |
| --- | --- |
| Display name | Word Search |
| Android package | `com.stagware.wordsearch` |
| iOS bundle id | `com.stagware.wordsearch` |
| Deep link scheme | `wordsearch://` |

The package name is **permanent** once published — Play identifies the app by it
forever and it cannot be changed. Change it now if `com.stagware.wordsearch` is
not what StagWare wants.

## Local build (no Expo account)

`android/` is generated, not committed. Regenerate it any time:

```bash
npx expo prebuild -p android
```

Then build a standalone APK:

```bash
cd android && ./gradlew assembleRelease
```

Output: `android/app/build/outputs/apk/release/app-release.apk`

Environment this machine needs (see the main README for the full list):

```bash
export ANDROID_HOME="$LOCALAPPDATA/Android/Sdk"
export JAVA_HOME="$PROGRAMFILES/Android/Android Studio/jbr"
```

### What that APK is and isn't

The Expo template signs the **release** variant with the *debug* keystore
(`android/app/build.gradle`, `signingConfig signingConfigs.debug`). That key is
the well-known Android debug key with password `android` — public, identical on
every machine, and **not a secret**.

So the APK you get is:

- Standalone. The JS bundle is embedded; it runs with no Metro server.
- Fine for sideloading, internal testing, and demos.
- **Not publishable.** Play rejects debug-signed uploads.

Note also that a `assembleDebug` APK is *not* standalone — it expects a Metro
dev server at runtime. Always use `assembleRelease` for an artifact you hand to
someone else.

## Going to production

### 1. Create the upload key

Run this yourself and choose your own password — this key is the identity of
StagWare's app and must not be lost or shared:

```bash
keytool -genkeypair -v -storetype PKCS12 -keystore stagware-upload.keystore -alias stagware-upload -keyalg RSA -keysize 2048 -validity 10000
```

Store the keystore outside the repo. Put the credentials in
`~/.gradle/gradle.properties` (user-level, never committed):

```properties
STAGWARE_UPLOAD_STORE_FILE=/absolute/path/to/stagware-upload.keystore
STAGWARE_UPLOAD_KEY_ALIAS=stagware-upload
STAGWARE_UPLOAD_STORE_PASSWORD=...
STAGWARE_UPLOAD_KEY_PASSWORD=...
```

### 2. Wire it into the release build

`android/` is regenerated by `prebuild`, so hand-editing `build.gradle` gets
wiped. Make this change durable with an `expo-build-properties` config plugin or
a small custom plugin in `app.json` rather than editing the generated file.

The signing config it needs to produce:

```gradle
signingConfigs {
    release {
        storeFile file(STAGWARE_UPLOAD_STORE_FILE)
        storePassword STAGWARE_UPLOAD_STORE_PASSWORD
        keyAlias STAGWARE_UPLOAD_KEY_ALIAS
        keyPassword STAGWARE_UPLOAD_KEY_PASSWORD
    }
}
buildTypes { release { signingConfig signingConfigs.release } }
```

### 3. Enable Play App Signing

Strongly recommended. Google holds the actual app signing key; you only hold an
upload key. If the upload key is ever lost or compromised, Google can reset it —
without Play App Signing, a lost key means you can never update the app again.

### 4. Build an App Bundle, not an APK

Play requires AAB:

```bash
cd android && ./gradlew bundleRelease
```

Output: `android/app/build/outputs/bundle/release/app-release.aab`

### 5. Version every upload

`versionCode` must strictly increase on each upload; Play rejects duplicates.
Set both in `app.json` (`expo.version` and `expo.android.versionCode`) so
`prebuild` propagates them — editing the generated Gradle files does not stick.

## Still needed before submission

- **Real branding.** `assets/icon.png` and the three `android-icon-*.png` layers
  are stock Expo artwork. Play also wants a 512x512 store icon, a 1024x500
  feature graphic, and at least two phone screenshots.
- **Privacy policy URL.** Required for all new apps. This app collects nothing
  and makes no network calls, which makes the Data Safety form short but not
  optional.
- **Content rating questionnaire** and a target audience declaration.
- `expo-system-ui` if the `userInterfaceStyle` setting in `app.json` should
  actually apply — `prebuild` warns that it is currently ignored.
- iOS has never been built or run. It needs a Mac, an Apple Developer account
  ($99/yr), and its own signing setup.

## EAS alternative

If the local toolchain becomes a burden, `eas build -p android --profile
production` builds in Expo's cloud and manages the keystore for you. It needs an
Expo account and has monthly limits on the free tier. The trade-off is that
Expo then holds your signing key unless you explicitly upload your own.
